## 0. 一页纸摘要

**问题**：Nexiova 现在同时面对三个互相拉扯的矛盾——
1. 内容要深（否则空洞）vs. 第一次学不能太重（否则流失）
2. 叙事说"认知引擎"vs. 实现只是一个计分函数
3. 36 个学科的宽度 vs. 没有一个学科做到了深

**解法**：**多周目学习（Multi-Cycle Learning）**。同一颗星，走多遍，每一遍更深。

- 第 1 周目「初见」：建立地图和直觉，轻、快、有趣
- 第 2 周目「精读」：逐行推代码、逐步推公式，做题、拆解
- 第 3 周目「贯通」：跨学科迁移、出题、把知识教回给 AI
- 第 4+ 周目「守护」：间隔提取，维持记忆

它一次解决三个矛盾：深度被拆到时间轴上（矛盾 1）；认知向量获得"深度"这个第二维，且周目间的卡点记忆让"小助理认识你"变成可演示的事实（矛盾 2）；第 2/3 周目的内容只需要先为少数学科做深（矛盾 3）。

**学术锚点**：Bruner 螺旋式课程（1960）、Bjork "合意困难"（desirable difficulties）、间隔效应与提取练习（Roediger & Karpicke 2006）、Bloom 修订版分类（Anderson & Krathwohl 2001）、VanLehn 智能导学系统的"内环/外环"模型。游戏类比：New Game+。

## 1. 设计哲学：为什么是"多周目"而不是"更深的一次"

现在的星核探索试图在一次会话里从钩子走到总结。要加深度，只有两条路：把一次会话做得更长更重，或者把深度分摊到多次。前者已经被证明会伤害完成率（用户反馈"一次给太多"）。后者才是人类真实的学习方式——没有人第一次读《算法导论》就理解摊还分析。

多周目的三条原则：

1. **每一周目都是完整的、有收尾的。** 第 1 周目结束你就"会用"这颗星，不是"学了一半"。这保护了完成感。
2. **周目之间有记忆。** 小助理在第 2 周目开场就说"上次你在 X 卡了两次，这次我们从那里开始"。这是认知引擎最直接的可感知形态。
3. **难度递增是结构性的，不是数值性的。** 不是"题目变难"，而是 Bloom 层级上移、脚手架撤除、输出要求升级、干扰项从误区库来。

## 2. 周目定义

| 周目 | 名称 | Bloom 层 | 目标 | 小助理角色 | 核心卡片 | 输出要求 | 通过条件 |
|---|---|---|---|---|---|---|---|
| 1 | **初见** First Light | remember · understand | 建立地图、直觉、知道"有什么" | **导游**：热情、类比多、不批评、只在关键处停 | HOOK · PREDICT · TEACH · FLASH · 1 道 QUIZ（易）· ASK_SUMMARY | 用自己的话说出核心（≥20 字） | 总结不为空且不敷衍（AI 判） |
| 2 | **精读** Deep Dive | apply · analyze | 能做、能拆、知道"为什么" | **教练**：要求具体、纠错、不放水、答错先引导再补讲 | TEACH（短）· **CODE / DERIVE 逐行** · BLANK · 2–3 道 QUIZ（干扰项来自误区）· ASK_SUMMARY（"解释为什么"） | 逐行走完 + 题目 ≥2/3 一次对 | 达标；否则补讲后重测，仍不达标记欠条 |
| 3 | **贯通** Synthesis | evaluate · create | 迁移、创造、能教别人 | **对手 / 苏格拉底**：只问不答，用反例逼你 | 跨学科 HOOK · 迁移 PREDICT · 1 道融合 QUIZ（本星 + 相邻已学星）· **CREATE**（出题）· ASK_SUMMARY（"教给我"，按 rubric 评） | 设计一道好题 + 讲清楚 | AI rubric ≥ 阈值；不达标掉回第 2 周目 |
| 4+ | **守护** Maintain | retrieval | 记忆维持 | **回声**：极简、只测不讲 | RECALL · 1 道随机 QUIZ · LAYER_DONE | 答对 | 间隔调度（1/3/7/21 天） |

### 2.1 难度递增的七个机制

| 机制 | 第 1 周目 | 第 2 周目 | 第 3 周目 |
|---|---|---|---|
| Bloom 层级 | 记忆·理解 | 应用·分析 | 评价·创造 |
| 脚手架 | 提示随时给 | 答错一次后给 HINT | 不给提示 |
| 干扰项 | 明显错误 | 来自常见误区 | 来自"专家也会错"的边界情形 |
| 输出升级 | 认出 → 说出 | 推导 / 写出 / 拆解 | 出题 / 教学 / 批判 |
| 阻塞严格度 | 答错也可继续（记一笔） | 答错 → 补讲循环 | 答错 → 掉级 |
| 交织 | 单星 | 单星 + 前置回顾 | 融合相邻已学星 |
| 助理记忆 | 无 | 引用上周目卡点 | 引用全部历史 + 欠条 |

### 2.2 数据模型

```ts
type MasteryLevel = 0 | 1 | 2 | 3 | 4;   // 0 未学 · 1 初见 · 2 精读 · 3 贯通 · 4 守护

type CycleRecord = {
  cycle: number;
  startedAt: number;
  completedAt: number;
  quizTotal: number;
  quizFirstTry: number;
  wrongOptions: string[];      // 供误区挖掘
  summary?: string;            // 用户总结原文
  passed: boolean;
};

type NodeMastery = {
  nodeId: string;
  level: MasteryLevel;
  history: CycleRecord[];
  stickingPoints: string[];    // 小助理记下的一句话卡点，最多 5 条
  debts: string[];             // 未还欠条（echo id）
  lastTouched: number;
  nextReviewAt?: number;
};
```

- 存储 key：`qc_mastery`（`Record<nodeId, NodeMastery>`）
- 迁移：读旧的 `qicheng_universe_learned`（布尔集合）→ 全部转为 level 1，带一条合成的 CycleRecord
- 兼容：`getLearnedNodeIds()` 语义不变 = level ≥ 1，所有旧调用方无感
- 新 API：`getMastery(id)` · `getMasteryMap()` · `nextCycleFor(id)` · `recordCycleComplete(id, record)` · `addStickingPoint(id, text)` · `demote(id)`

### 2.3 认知向量的第二维

`cognition.ts` 的贡献函数从 `difficulty` 变为 `difficulty × levelWeight`：

| level | 权重 | 含义 |
|---|---|---|
| 1 | 0.4 | 宽度：知道存在 |
| 2 | 1.0 | 基准：会做 |
| 3 | 1.8 | 深度溢价：能迁移能教 |
| 4 | 2.0 | 守护：稳定 |

结果：只刷第 1 周目的人，认知向量永远只有 40%。这让"深度"第一次进入了系统的核心指标。

### 2.4 星的视觉等级（品牌落地）

Nova = 新星诞生。星的亮度就是周目：

| level | 视觉 |
|---|---|
| 0 | 暗星（现状 available） |
| 1 | 点亮（emissive 0.9，小光晕） |
| 2 | 明亮（emissive 1.3，光晕 0.3） |
| 3 | **新星**（emissive 1.8，光晕 0.45，脉冲环） |
| 4 | 恒定金色调 |

节点面板显示「第 N 周目」徽章和「开始第 N+1 周目」按钮；路线栏用亮度区分。

### 2.5 教学协议接入

- `/api/node-learn` 请求新增 `cycle: 1–4` 和 `memory: { stickingPoints, debts, prevSummary }`
- `buildExplorePrompt` 按周目分支：角色块 + 该周目流程；第 2 周目强制 CODE/DERIVE；第 3 周目强制 CREATE 与融合题
- 收尾新增 `[[STICK]]` 标记：AI 用一句话写下本周目观察到的卡点（"对递归终止条件的理解不稳"），前端存入 `stickingPoints`，并以「小助理记下了」小卡片呈现——**这是让用户看见"它在了解我"的最小可感知单元**
- GAIN 命名按周目：初见 → "直觉"，精读 → "技能"，贯通 → "视角"
- `composeScript(node, cycle)` 替代按 status 的分支；造物主模式成为第 3 周目的固定环节

### 2.6 计划宇宙的 NG+

## 3. 认知闭环 MVP：缺口诊断

只做一个闭环，做到能演示。

```
QUIZ 两次答错（第 2 周目及以上）
  → diagnoseGap(nodeId, graph, masteryMap)
      沿 prerequisites BFS（深度 ≤ 2）
      找出 mastery.level < 要求（当前周目 − 1）的前置节点，按距离排序
  → 有缺口：注入 GAP 卡「这道题卡住，可能欠的是「X」」+ 「回炉 X」按钮
      同时记欠条（echo debt）+ 写入 mastery.debts
  → 无缺口：走现有 chat 阶段，带上错误选项做针对性重讲（错误纠正刺激）
```

这是"答错 → 诊断 → 补课"的最小闭环。它用到了图（前置关系）、用到了掌握度（level）、产生了可回收的欠条。之后的迁移识别、欠条感知规划都是在这条路上加东西。

## 9. 度量：怎么知道它有效

| 指标 | 含义 | 目标（首月） |
|---|---|---|
| 二周目回访率 | 完成第 1 周目的节点中，30 天内开启第 2 周目的比例 | ≥ 25% |
| 首次正确率提升 | 同一节点第 2 周目 vs 第 1 周目的 quiz 一次正确率差 | 正向 |
| 欠条清偿率 | 记下的欠条中被"回炉"的比例 | ≥ 40% |
| 卡点命中 | 用户对「小助理记下了」卡片的确认率（👍/👎） | ≥ 70% 👍 |
| 会话完成率 | 第 1 周目从 HOOK 到 GAIN 的完成率 | 不低于改造前 |

事件已接 `trackEvent`，需要落到持久化存储后才能真正统计（见 §7）。
