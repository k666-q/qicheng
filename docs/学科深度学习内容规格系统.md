# 启程 · 学科深度学习内容规格系统（执行文档）

> 版本：v1.0（2026-07-07）
> 目标：解决「学习内容空洞、停留在了解层面」的根本问题。给每个知识节点配一份**结构化的教学规格书（LearningSpec）**，AI 严格按规格逐层教学、逐层验证，不允许即兴发挥。
> 定位：本文档是**标准模板**——按第七章的操作步骤，可以直接为任何新学科生成规格，无需重新设计。
> 权威依据：ACM/IEEE-CS/AAAI《Computer Science Curricula 2023》（CS2023）、布鲁姆认知目标分类修订版（Anderson & Krathwohl 2001）、Stanford CS161/CS166 与 MIT 6.1210 课程大纲、AP Physics C 课程框架、Polya 解题四阶段、5E 教学模型。

---

## 一、问题诊断（为什么现在的内容是空洞的）

当前每个知识节点只有 `name + plain_name + description + keywords + difficulty` 五个字段，AI 拿到这些就即兴发挥。导致四个结构性缺陷：

| 缺陷 | 表现 | 根因 |
|------|------|------|
| 覆盖不完整 | 讲了 AVL 旋转的概念，跳过 LL/RR/LR/RL 四种类型的区别 | 没有「必须覆盖清单」，AI 讲什么全靠运气 |
| 深度不够 | 只讲"为什么旋转"，不讲"旋转代码怎么写" | 没有「教到什么程度」的层级定义 |
| 没有层次 | "理解原理"和"能写代码"和"能分析复杂度"混在一锅 | 没有认知层级的递进和逐层验证 |
| 缺知识点 | 知识图谱里根本没有"平衡因子计算"这个节点 | 图谱生成靠 AI 一次性输出，没有对照权威知识体系 |

**解决思路**：内容规格化。每个知识节点 = 一份 LearningSpec（学习规格书），规定必须覆盖什么、每层教到多深、怎么才算过关。AI 的自由度只保留在「表达方式」（现有刺激式教学不变），**内容覆盖度和深度由规格强制**。

## 二、核心数据结构：LearningSpec

新文件：`src/lib/learn/spec-types.ts`

```typescript
/** 一个知识节点的完整学习规格书 */
export type LearningSpec = {
  nodeId: string;
  /** 学科域，决定使用哪个学科模板 */
  discipline: DisciplineId;
  /** 认知层序列：按顺序逐层教学，上一层通过才进入下一层 */
  layers: ContentLayer[];
  /** 先决知识：学这个之前必须已经会什么（nodeId 或纯文本描述） */
  prerequisites: string[];
  /** 学完解锁什么（用于图谱连边与"为什么学这个"的动机说明） */
  unlocks: string[];
  /** 常见误区清单：AI 出题和讲解时必须主动针对（源自概念测评研究的错误概念库思路） */
  misconceptions: string[];
};

export type DisciplineId =
  | "cs"          // 计算机/编程/算法
  | "math"        // 数学
  | "physics"     // 物理
  | "language"    // 语言类
  | "humanities"  // 人文社科
  | "general";    // 兜底

/** 认知层：一层 = 一次独立的 AI 请求 = 一组卡片 = 一个通过判定 */
export type ContentLayer = {
  id: string;                 // 如 "avl-l3-code"
  level: BloomLevel;
  /** 该层的可测量学习目标（必须用行为动词，禁止"了解/知道"这类模糊词） */
  objective: string;
  /** 该层必须覆盖的知识点清单（AI 输出后可核对，缺一即重新生成） */
  mustCover: string[];
  /** 该层要求 AI 产出的内容类型与硬约束 */
  output: OutputRequirement[];
  /** 通过标准：满足才解锁下一层 */
  passCriteria: PassCriteria;
  /** 该层预算（动态 max_tokens 依据） */
  tokenBudget: number;
};

/** 布鲁姆修订版六级。层级序列不必六级全有，但顺序不可颠倒 */
export type BloomLevel =
  | "remember"    // 记忆：能说出术语、分类、规则
  | "understand"  // 理解：能用自己的话解释为什么
  | "apply"       // 应用：能手动执行/计算/写出
  | "analyze"     // 分析：能拆解、对比、诊断错误
  | "evaluate"    // 评价：能权衡方案、判断适用场景
  | "create";     // 创造：能设计新题/新方案/教别人

export type OutputRequirement =
  | { kind: "concept"; maxChars: number }
  | { kind: "code"; language: string; maxLines: number; mustInclude: string[]; lineByLine: boolean }
  | { kind: "derivation"; maxSteps: number; stepByStep: boolean }
  | { kind: "example"; count: number; contrasting?: boolean }   // contrasting=正反例对照
  | { kind: "exercise"; format: "choice" | "fill" | "code_fill" | "trace" | "debug" | "free"; count: number }
  | { kind: "comparison"; items: string[] }
  | { kind: "visual"; description: string };                    // 需要图示/Manim 的段落

export type PassCriteria = {
  /** 必须答对的练习数（对应 output 中的 exercise） */
  minCorrect: number;
  /** 允许错几次后触发补讲（AI 追加讲解后重出变体题） */
  maxAttemptsBeforeReteach: number;
  /** 是否要求用户主动确认（如"懂了，继续"按钮）——防止自动滑过 */
  requireConfirm: boolean;
};
```

### 设计要点

1. **一层一请求**：彻底解决"一次性生成 3500 token 装不下深度内容"的问题。每层独立请求，`max_tokens` 按 `tokenBudget` 动态设定，上一层的产出摘要作为下一层的上下文。
2. **mustCover 可核对**：AI 输出后，前端/后端按清单核对关键词覆盖度，缺失则带着缺失项重新请求（最多 2 次）。
3. **passCriteria 是硬门**：不过不放行。答错触发补讲（复用 chat 模式，针对错误选项讲），补讲后出**变体题**而不是原题。
4. **misconceptions 前置**：出题优先打误区（这是概念测评 Concept Inventory 的核心方法——题目的干扰项来自真实的常见错误概念）。

## 三、学科模板标准（模板的模板）

**一个学科模板 = 回答以下六个问题**。新增学科时照着填即可（详见第七章操作步骤）。

| # | 问题 | 产出物 |
|---|------|--------|
| T1 | 这个学科的**特征活动**是什么？（学会的人和没学会的人，行为差异在哪） | 特征活动清单，如 CS=写代码/调试，数学=推导/证明 |
| T2 | 权威知识体系是什么？ | 知识域骨架（对照 ACM CS2023 / 大学课程大纲 / AP 框架等） |
| T3 | 每个认知层的**标准输出类型**是什么？ | BloomLevel → OutputRequirement 的默认映射表 |
| T4 | 每层的**标准检验方式**是什么？ | 练习 format 与 passCriteria 默认值 |
| T5 | 这个学科的**高频误区模式**有哪些？ | 误区模式库（供生成 misconceptions 时参考） |
| T6 | 深潜（逐行/逐步）的**推进单位**是什么？ | 数学=一步变换；代码=一行/一小块；语言=一个成分 |

模板落地为代码：`src/lib/learn/discipline-templates.ts`

```typescript
export type DisciplineTemplate = {
  id: DisciplineId;
  /** 学科关键词：用于从 subjectName 自动判定 discipline */
  matchKeywords: string[];
  /** 特征活动（T1）：注入 prompt，强制 AI 围绕这些活动组织内容 */
  signatureActivities: string[];
  /** 各认知层的默认输出配置（T3+T4），生成 spec 时可被节点级覆盖 */
  layerDefaults: Record<BloomLevel, { output: OutputRequirement[]; pass: PassCriteria; tokenBudget: number }>;
  /** 误区模式（T5） */
  misconceptionPatterns: string[];
  /** 深潜推进单位（T6） */
  deepDiveUnit: "code_line" | "derivation_step" | "sentence_part" | "causal_link";
};
```

## 四、三个已定稿的学科模板

### 4.1 计算机 / 编程 / 算法（discipline: "cs"）

**T1 特征活动**：读代码、写代码、追踪执行（trace）、调试（debug）、复杂度分析。核心铁律：**没有代码的算法学习是无效的**。

**T2 权威体系**：ACM CS2023 · Algorithmic Foundations（AL）知识域，五个知识单元（见第五章骨架库）。

**T3+T4 层级默认配置**：

| 层级 | 目标模式 | 必须的输出 | 检验方式 | 通过标准 |
|------|---------|-----------|---------|---------|
| remember | 能说出术语、分类、适用条件 | concept（≤300字）+ example×1 | choice×1 | 1/1 对 |
| understand | 能解释「为什么这样设计」「不这样会怎样」 | concept（≤400字）+ visual + 反事实提问 | choice×2（干扰项=误区） | 2/2 对，错1次补讲 |
| apply | 能**手动执行**算法（纸上跑一遍） | derivation（分步推演，≤8步，逐步展示）| trace×1（给输入，推中间状态） | 1/1 对 |
| apply(code) | 能写出/补全核心代码 | code（≤30行，逐行注释，lineByLine=true）| code_fill×2（挖掉关键行） | 2/2 对，错1次给 HINT 不给答案 |
| analyze | 能诊断错误代码、分析复杂度来源 | code（含1个典型bug）+ derivation（复杂度推导≤5步） | debug×1 + choice×1 | 2/2 对 |
| evaluate | 能对比同类方案、判断选型 | comparison（vs 至少1个同类结构/算法） | choice×1（场景选型题） | 1/1 对 |
| create | 能设计能骗过80%人的题 / 变体方案 | 造物主任务（复用现有 CREATE） | free，AI 按 misconceptions 评审 | AI 评审通过 |

注意：cs 的 apply 拆成两层（手动执行 + 写代码），这是该学科的特征强化。

**T5 误区模式**：边界条件遗忘（空/单元素/满）、递归基例错误、复杂度混淆（最好/最坏/均摊）、指针/引用更新顺序错误、循环不变量破坏。

**T6 深潜单位**：`code_line`——按功能模块分块，块内逐行，块完做整体回看（沿用 DeriveCard 已实现的机制）。

**完整示例：「AVL 树旋转」的 LearningSpec**

### 4.2 数学（discipline: "math"）

**T1 特征活动**：逐行推导、证明、计算、识别定理适用条件。核心铁律：**没有推导的数学学习是无效的**。方法论依据：Polya 四阶段（理解题意→拟定方案→执行方案→回顾）+ 程序性流利与概念性理解并重。

**T3+T4 层级默认配置**：

| 层级 | 目标模式 | 必须的输出 | 检验方式 | 通过标准 |
|------|---------|-----------|---------|---------|
| remember | 能写出定义/定理陈述/公式本体 | concept（≤300字）+ 公式（FLASH 卡） | fill×1（默写公式关键部分） | 1/1 |
| understand | 能说出每个符号的含义、定理的适用条件与失效场景 | concept + example×2（contrasting：一个适用一个不适用） | choice×2 | 2/2 |
| apply | 能完成标准计算/套用 | derivation（例题逐步演算≤8步） | fill×2（中间步骤留空） | 2/2 |
| analyze | 能**逐行跟完整推导/证明**，说出每步用了什么规则 | derivation（完整推导，stepByStep，每步带规则名）→ 走 DeriveCard | blank×2 + counterfactual×1（"删掉这步会坏在哪"） | 3/3，卡住可递归下潜 |
| evaluate | 能判断多种解法的优劣、选择工具 | comparison（≥2种解法同一题） | choice×1 | 1/1 |
| create | 能出变式题/给出新证明思路 | 造物主任务 | free | AI 评审 |

**T5 误区模式**：符号滥用（如对非独立变量求导）、条件遗忘（分母为零/收敛性/定义域）、逆命题误用（把充分当必要）、极限与取值混淆。

**T6 深潜单位**：`derivation_step`——前提→结论的推导链，一步一个变换规则（DeriveCard 的 derivation kind 已支持）。

### 4.3 物理（discipline: "physics"）

**T1 特征活动**：预测-观察-解释（POE）、建模（从现象抽象出物理模型）、公式推导、量纲/极限检验。方法论依据：5E 模型 + AP Physics 科学实践框架（每个学习目标绑定一种科学实践）。

**T3+T4 层级默认配置**：

| 层级 | 目标模式 | 必须的输出 | 检验方式 | 通过标准 |
|------|---------|-----------|---------|---------|
| remember | 能陈述定律、公式、单位 | concept + FLASH | fill×1 | 1/1 |
| understand | 能用自己的话解释物理图像（为什么，而非是什么） | concept + visual（Manim 动画优先） + PREDICT×1（先猜现象再揭示） | choice×1 | 2/2 |
| apply | 能代入公式解标准题 | derivation（例题≤6步） | fill×2 | 2/2 |
| analyze | 能从定律推导出公式；能做量纲检验和极限检验 | derivation（完整推导，stepByStep）→ DeriveCard | blank×2 + counterfactual×1（"如果质量趋于无穷这个式子还对吗"） | 3/3 |
| evaluate | 能判断该用什么定律解一个新情境（能量法 vs 牛顿定律） | comparison + 场景选型题 | choice×1 | 1/1 |
| create | 能设计一个思想实验/实验方案验证结论 | 造物主任务 | free | AI 评审 |

**T5 误区模式**：力与运动混淆（有力才有运动）、矢量标量混淆、平均值与瞬时值混淆、忽略参考系。

**T6 深潜单位**：`derivation_step`。

### 4.4 其他学科（骨架，按需细化）

- **language（语言类）**：特征活动=句子逐成分拆解、仿写、语境运用。深潜单位=`sentence_part`。apply 层强制「仿写练习」，analyze 层强制「病句诊断」。
- **humanities（人文社科）**：特征活动=因果链重构、多视角论证、史料/证据评价。深潜单位=`causal_link`。analyze 层强制「论证链补全」，evaluate 层强制「对立观点对比」。
- **general（兜底）**：沿用现有六级默认配置，输出以 concept + example + exercise 为主。

## 五、知识域骨架库（保证图谱完整性）

问题：现在知识图谱靠 AI 一次性生成，粒度与覆盖度不可控。解法：**权威骨架 + AI 填充**。生成图谱时把对应领域的骨架注入 prompt，要求 AI 的节点划分对齐骨架、不得遗漏 CS Core 级知识点。

新文件：`src/lib/learn/domain-skeletons.ts`（数据文件，每个领域一个骨架）

### 5.1 数据结构与算法（对照 ACM CS2023-AL，五个知识单元）

```
AL-Foundational 基础数据结构与算法
├─ 线性结构：数组 / 链表(单/双/循环) / 栈 / 队列 / 双端队列
├─ 散列：哈希函数 / 冲突处理(链地址/开放寻址) / 负载因子与扩容
├─ 树：二叉树 / BST / AVL(平衡因子·四种旋转) / 红黑树 / B树·B+树 / 堆 / Trie
├─ 图：表示法(邻接矩阵/表) / 有向无向 / 加权图
├─ 集合类：集合 / 并查集(按秩合并·路径压缩)
├─ 搜索：线性 / 二分(及变体) / 插值

└─ 图算法基础：BFS / DFS / 最短路(Dijkstra/Bellman-Ford/Floyd) / 最小生成树(Prim/Kruskal) / 拓扑排序
AL-Strategies 算法策略
├─ 递归与迭代 / 分治 / 贪心(及其失效场景) / 动态规划(重叠子问题·最优子结构)
├─ 回溯 / 分支限界 / 随机化 / 启发式 / 空间换时间
AL-Complexity 复杂度分析
├─ 渐进符号(O/Ω/Θ) / 最好·最坏·平均 / 递归方程求解(主定理) / 摊还分析
└─ P与NP / NP完全 / 归约(概念级)

```

### 6.2 分段请求架构（一层一请求）

```
进入节点
  ├─ ① GET spec（spec-store 有缓存则直接用；无则调 /api/node-spec 生成并缓存）
  ├─ ② 开场：现有 explore 的 HOOK+PREDICT（保留刺激式开场，不变）
  ├─ ③ 逐层循环：for layer of spec.layers
  │     ├─ 请求 /api/node-learn { phase:"layer", layer, prevSummary }
  │     │    max_tokens = layer.tokenBudget；prompt = 模板注入 objective/mustCover/output/misconceptions
  │     ├─ 前端渲染该层卡片（TEACH/CODE/DERIVE/QUIZ...）
  │     ├─ mustCover 核对：后端流结束后校验关键词覆盖，缺失→自动带缺失清单重请求（≤2次）
  │     ├─ 用户作答 → passCriteria 判定
  │     │    ├─ 通过 → 该层完成，写入 session，进入下一层
  │     │    └─ 未通过 → chat 模式补讲（针对错误选项）→ 出变体题 → 再判定
  │     └─ 层完成状态持久化（刷新恢复到当前层）
  └─ ④ 收尾：现有 closing（FEEDBACK/GAIN/GIANT...），GAIN 改为确认领取
```

关键约束：

- **语义切割**：如果某层内容天然超预算（如长推导），AI 在 prompt 中被要求按语义单元自行分块，输出 `[[CONTINUE]]` 标记，前端自动续请求，直到该层完输出 `[[LAYER_DONE]]`。
- **上下文压缩**：跨层只传「上一层的 mustCover 清单 + 用户答题结果」，不传全文，控制 token 成本。
- **质量优先**：单层重试上限 2 次，仍失败则降级为现有单流模式并记录（不阻塞用户）。

## 七、新增学科操作步骤（标准流程，照做即可）

新增一个学科（如「经济学」）只需五步，预计 1-2 小时人工工作量：

1. **填 T1**：写出 3-5 个特征活动（经济学：画供需图、边际分析、读懂数据图表、模型假设检验）。
2. **填 T2**：找 1-2 个权威课程体系（如 AP Economics / 曼昆目录），整理知识域骨架加入 `domain-skeletons.ts`。
3. **填 T3+T4**：复制最接近的现有模板（偏推导→math，偏分析论证→humanities），逐层调整 output 与检验 format。**每层 objective 必须用可测量的行为动词**（说出/画出/计算/判断/设计），禁止「了解/掌握/熟悉」。
4. **填 T5+T6**：列 4-6 个高频误区模式；确定深潜推进单位。
5. **注册**：在 `discipline-templates.ts` 加入模板对象和 matchKeywords，跑一个节点端到端验证。

**质量红线（每个模板必须满足，否则不予合并）**：

- [ ] 层级 ≥ 5 层（remember 到 create 至少覆盖 5 级）
- [ ] 每层都有 mustCover（≥2 项）和可判定的 passCriteria
- [ ] apply 层必须包含该学科的特征活动（cs=写代码，math=推导，physics=推导+检验……）
- [ ] 至少 1 层走深潜（DeriveCard）
- [ ] misconceptionPatterns ≥ 4 条，且 QUIZ 干扰项被要求取自误区

## 九、风险与对策

| 风险 | 对策 |
|------|------|
| spec 生成质量不稳（DeepSeek JSON 跑偏） | zod 严格校验 + 重试 2 次；失败降级为 general 模板默认 spec；高频节点的 spec 可人工审校后固化进代码 |
| 逐层门控太严导致挫败 | 每层 maxAttemptsBeforeReteach 后必有补讲；连续 2 层卡住弹出「降低难度/跳过本层（星等停留）」选项，跳过不算通过 |
| 单节点学习时长大幅增加 | 层级进度可视化（"3/7 层"）+ 随时中断续学（B4 持久化保证）；remember/understand 两层合并为一次请求以缩短前期 |
| token 成本上升 | 跨层上下文只传摘要；spec 有缓存一次生成多次使用；tokenBudget 上限硬控 |
| 中文文件名/编码（历史教训） | 所有源文件用工具写入，禁止 shell 管道处理中文文件 |

## 十、验收标准（总）

1. 计算机节点：学完后用户**见过并补全过真实代码**、修过一个 bug、做过一次复杂度推导——缺一即未达标。
2. 数学节点：学完后用户**逐行跟完过完整推导**、独立补全过至少 2 个中间步骤。
3. 任何节点：每一层都有明确的通过判定，不存在"什么都没做就获得思维"的路径。
4. 刷新页面后恢复到当前层、已完成层的卡片保持完成态。
5. 新增一个学科模板 ≤ 2 小时人工工作量，且自动通过第七章质量红线检查。
